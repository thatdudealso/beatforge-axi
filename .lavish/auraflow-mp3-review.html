01 / Flow

AuraFlow → BeatForge

Orchestrators shell out to beatforge-axi. Success is TOON status: ok plus a playable MP3 on disk. Missing weights or FFmpeg fail closed — no silent fallback to proprietary services or NC weights.

flowchart LR AuraFlow["AuraFlow orchestrator"] -->|"beatforge-axi --engine … generate"| CLI["beatforge-axi CLI"] CLI --> Registry["Engine registry"] Registry --> Synth["synth\nstdlib drone + FFmpeg"] Registry --> AceStep["acestep\nMIT turbo when ready"] Synth --> MP3["out.mp3\naudible"] AceStep --> MP3 AceStep -->|"weights missing"| Err["TOON engine_unavailable"] Human["Human reviewer"] --> CueLab["CueLab deck\nwaveform + accept"] CueLab --> API["/v1 loopback API"] API --> Registry
A

Plumbing (done)

beatforge-axi --engine synth generate \
  --prompt "soft focus drone" \
  --duration 15 \
  --out /tmp/auraflow-bf-synth.mp3

Returns status: ok and a real MP3. Requires ffmpeg on PATH.

02 / UI

CueLab deck (current scaffold)

CueLab is BeatForge’s Lavish-analogue human surface: waveform platter, generate controls, and (eventually) accept/reject on returned artifacts. Screenshots below are from the live React/Vite app running locally — not mocks.

Working today

  • Deck layout and turntable platter
  • Easy / Advanced mode switch
  • Engine capability gating
  • Generate submits to /v1/jobs/generate

Not yet

  • Play generated MP3 in browser
  • Real waveform from audio bytes
  • Accept / reject acceptance board
  • Job progress SSE

Lavish parity

lavish-axi reviews HTML artifacts with annotate + queue feedback. CueLab will review audio artifacts with waveform selection and human sign-off — same AXI loop, different medium.
